# Record contract 3

Normative companion to [the implementation handoff](../implementation-handoff.md). This specifies JSON bodies and cross-record rules. Implement these as closed schemas and relational validation in the shared core; SQLite alone does not validate the mathematical record structure.

## 1. Common types and identity

`ID` is a case-sensitive string matching `^[A-Za-z][A-Za-z0-9_-]*$`, with at most 128 characters. Imported valid overview IDs are preserved. New IDs come from the tool as `<prefix>_<UUIDv4 hex without hyphens>`. Prefixes are listed below. A printed theorem number is never a primary key. Splits/merges use explicit mappings; retired IDs are never recycled.

`Ref = {"collection": Collection, "id": ID}`. `PinnedRef = {"collection": Collection, "id": ID, "version": positive_integer}`. `Target` restricts Ref to `items` or `parts`. `AnchorRef` is an anchor ID; its exact version is captured by generated evidence bindings. A stable reference follows current identity; historical checks always resolve their bindings against exact versions/facets, never silently against today's source.

`Statement = {"form": "verbatim"|"transcription"|"synopsis", "text": nonempty_string}`. Math remains LaTeX in text and is converted for display. `Passage = {"role": "statement"|"proof"|"definition"|"evidence", "anchor_id": ID}`. `Origin = "source"|"reconstruction"|"proposed_repair"`.

The notation in the field tables is exact: `?` means nullable, not omitted; `[T]` means an array, possibly empty unless stated otherwise; `enum(...)` is a closed allowed list. **All listed fields are required in a stored body. Unknown fields are rejected.** Commands may provide documented shorthand but expand defaults before validation. Empty text is permitted only for draft reasoning and explicitly described optional prose. Use `null` for an absent optional scalar, `[]` for an absent list. Do not silently drop unrecognized imported fields.

The export envelope for one record is `{collection, id, version, revision, retired, body}`. The six envelope keys are generated by the store except identity on creation. `version` starts at 1 and increases by one for an identity. A tombstone has `retired: true, body: null`. Ordinary authored edits contain only the batch fields defined in the handoff. Hashes, timestamps, currentness, colors, counts, bindings, generated excerpts, and adjacency indexes are not worker-authored fields.

The example uses readable fixture IDs permitted by this syntax; production authoring uses the ID allocator. To replay it, first initialize a disposable database, obtain an author packet permitting this inventory/argument scope, and replace `pkt_example` and `req_example` with real tool-issued packet/request identities. The example is a valid edit-body fixture, not a packet that already exists in the runtime.

### 1.1 Reference index paths and relation queries

`record_refs.field_path` is a canonical JSON Pointer relative to the record body, identifying one reference occurrence. Do not prefix it with `/body`. Escape property-name tokens by replacing `~` with `~0` and `/` with `~1`; array indices are zero-based decimal with no leading zeros. Structured Ref/PinnedRef values are indexed at the object itself, not at its `id` child. Scalar foreign IDs use their scalar's path. For example:

| Body reference | Indexed path | Target version |
|---|---|---|
| Use's `from` Target | `/from` | null, meaning a live reference |
| Scope's first and second assumptions | `/assumptions/0`, `/assumptions/1` | null for each |
| Item passage's anchor ID | `/passages/0/anchor_id` | null |
| Use's group ID | `/group_id` | null |
| Check's pinned predecessor | `/supersedes` | Explicit PinnedRef version |
| Anchor's source ID plus source version | `/source_id` | The paired `source_version` value |

Generate one row for each schema-designated record-reference occurrence, including the same target repeated at different array positions. Null references and empty arrays create no rows. Infer the collection for scalar IDs from their declared field meaning, not from an ID prefix. Do not index arbitrary prose, packet IDs, blob hashes, or external historical strings such as `Mapping.old`. The generated row set must match the immutable owner body exactly; replacing a list creates a new owner version and a new set of indexed paths.

Current membership queries join `record_refs` to the owning `record_heads` on collection, ID, and version, and exclude retired owner versions. This avoids counting historical links. Filter by the exact field path and referenced target below, deduplicate owner identities, and hash their sorted `(collection, id, version)` tuples. Empty membership is an explicit hashed empty list. Keys are collection-qualified Refs.

| Relation | Owner collection and reference path | Key collection |
|---|---|---|
| incoming_uses | uses, `/to` | items or parts |
| uses_in_group | uses, `/group_id` | groups |
| groups_in_argument | groups, `/argument_id` | arguments |
| arguments_for_target | arguments, `/target` | items or parts |
| parts_of_item | parts, `/item_id` | items |
| coverage_in_argument | coverage, `/argument_id` | arguments |
| scopes_in_argument | scopes, `/argument_id` | arguments |
| checks_or_findings_for_target | checks or findings, `/target` | The queried target's collection |

For historical queries, select each owner's latest version at or before the requested revision instead of joining today's heads. An unpinned target also resolves at that historical revision; a pinned target resolves its exact version. The foreign key to `record_heads` guarantees identity existence, not historical version selection.

## 2. Sources and source comparison

| Collection | Complete body fields |
|---|---|
| papers | `title: string; source_root: string; main_items: [ID]; report_paths: [string]` |
| sources | `paper_id: ID; path: string; media_type: enum(tex,pdf,bib,text,other); blob_sha256: string; capture_method: string; limitation: string?` |
| anchors | `source_id: ID; source_version: integer; locator: Locator; excerpt: string; excerpt_sha256: string; method: enum(exact_lines,label_match,exact_relocation,reviewed_page,reviewed_span); limitation: string?` |
| observations | `target: Ref; result: enum(matched,needs_attention); reviewer: string; note: string; evidence_refs: [ID]` |
| source_issues | `source_id: ID; anchor_id: ID?; category: enum(unresolved_branch,ambiguous_label,missing_source,missing_citation,locator_limit,other_resolution); description: string; lifecycle: enum(open,resolved,superseded); resolution: string?; reviewer: string` |
| source_reviews | `source_refs: [PinnedRef]; anchor_refs: [PinnedRef]; purpose: enum(branch_selection,locator_confirmation,context_change); decision: enum(accepted,unresolved); rationale: string; reviewer: string` |

`Locator` has exactly `start_line: integer?, end_line: integer?, page: integer?, label: string?`. Lines and PDF page are one-based inclusive. Start/end must appear together and satisfy start <= end. At least one location method is provided. `page` requires a PDF source. A TeX line never becomes a PDF page. `label` is the actual source label; human printed numbering stays in the item. Capturing sources and resolving locators are dedicated commands. They generate hashes and excerpts from bytes rather than trusting an agent-supplied excerpt.

Source versions retain old blobs. Sources never store independently authored dependency lists. One candidate citation inventory covers statement, proof, and relevant context passages. A no-proof external restatement has citation/source-verification obligations, not an invented local proof. Custom conditional selection has a source review/limitation path shared by inventory, packets, and final checks.

An observation pins the compared statement/use facets and source bindings through generated `evidence_bindings`. `matched` means faithful representation of the source. It never supplies a supported proof check. Completed observations and accepted source reviews are immutable; append a successor judgment if the reviewer changes their mind.

## 3. Statements, scopes, and proof structure

| Collection | Complete body fields |
|---|---|
| items | `kind: enum(assumption,definition,lemma,proposition,theorem,corollary,external_result,intermediate_result); label: string; caption: string; statement: Statement; passages: [Passage]; aliases: [string]; uncertainty: string?; origin: Origin; owner_id: ID?; scope_id: ID?` |
| parts | `item_id: ID; label: string; statement: Statement; passages: [Passage]; scope_id: ID?; origin: Origin` |
| scopes | `argument_id: ID?; parent_id: ID?; assumptions: [Target]; binders: [Binder]; conditions: [string]; evidence_refs: [ID]` |
| arguments | `target: Target; label: string; origin: Origin; scope_id: ID; final_group_id: ID?; evidence_refs: [ID]; lifecycle: enum(draft,registered,retired)` |
| groups | `argument_id: ID; conclusion: Target; kind: enum(joint,cases); scope_id: ID; case_scope_ids: [ID]; discharges: [ID]; rationale: string; evidence_refs: [ID]` |
| uses | `from: Target; to: Target; type: enum(dependency,definition,proof_argument); group_id: ID?; reason: string; needed_form: Statement?; substitutions: [Substitution]; evidence_refs: [ID]; regime: string?; uncertainty: string?` |
| coverage | `argument_id: ID; anchor_id: ID; start_offset: integer; end_offset: integer; classification: enum(substantive,structural); claim_refs: [Target]; check_ids: [ID]; note: string` |

`Binder = {"symbol": string, "domain": string, "quantifier": "fixed"|"forall"|"exists"}`. `Substitution = {"symbol": string, "value": string}`. These preserve interpretation for review; they are not a formal symbolic logic engine.

Required invariants:

1. An intermediate item has exactly one `owner_id`, pointing directly to a major item. A major item has `owner_id: null`. A part belongs to a major item. All containment and parent-scope chains are acyclic. Containment is not a proof dependency.
2. A source-origin statement has at least one source passage before its fidelity review can complete. During extraction, a draft item may have no passage and remains visibly unbound. A reconstruction or repair keeps its origin even after successful checking.
3. An argument is one complete route to exactly one item or part. Multiple arguments for that target are alternative routes, not mandatory cases. All written routes remain in full-audit coverage. A successful route cannot erase another written route's defect.
4. A group is one local inference. Its required inputs are exactly its member uses, derived by `uses.group_id`. Do not add an independently editable `input_ids` array to the argument/group. `uses.to` equals its group's conclusion. An input-free group is allowed for direct reasoning, and still needs a derivation check.
5. `joint` means all inputs are needed together for this inference. `cases` means its case scopes must jointly cover the target regime and their conclusions must be assembled. For `joint`, `case_scope_ids` is empty. For `cases`, it is nonempty and requires a `case_coverage` check. Individual case subderivations are groups under their proper local scopes; they feed the assembly through uses.
6. A registered argument has a non-null final group whose conclusion equals the argument target. Intermediate claims used in an argument have their establishing groups/arguments identified through actual uses and the work queue. A claim may be reused by multiple routes; its scope cannot be widened by graph traversal.
7. Root scopes have `parent_id: null`. A scope local to an argument names that argument. A paper/global scope has `argument_id: null`. `groups.discharges` contains scope IDs, never binder strings or assumption IDs. Each discharged scope must be local to that argument, or a case scope explicitly assembled by it, with an ancestor scope defining the exported conclusion. Its check explains which assumptions, binders, or conditions are discharged and what remains; it cannot silently discard the entire scope. A `scope_discharge` check is required for nonempty `discharges`; do not infer universal quantification from a fixed point.
8. Overview-only uses may have `group_id: null`. They preserve the current overview map and remain unassessed. A use required in a proof audit must be assigned to a group before its application check can complete. Overview import does not invent group semantics from the old free-text `regime`.
9. Two applications of the same result get two use IDs. Retargeting an existing use to a newly exposed intermediate preserves the use ID only if it is the same actual application and evidence. Separate alternatives/cases keep their own application records.
10. Coverage offsets are zero-based half-open Unicode code-point offsets within the captured anchor excerpt. Validate bounds mechanically. Coverage may overlap intentionally when a passage supports several claims. The union covers every in-scope proof passage; uncovered substantive spans remain work. Structural coverage has empty claim/check lists and no proof verdict. Substantive draft coverage may have no completed check yet and remains incomplete. No record is required per physical line.

### Example semantics

Given assumptions \(\Pr(A)\ge 1-\delta\) and \(\Pr(B)\ge 1-\delta\), a hidden claim can record \(\Pr(A\cap B)\ge 1-2\delta\). Its group has two uses, one from each premise. A later final composition claiming \(1-\delta\) is a separate obligation and is not established by those uses. The [example batch](example-batch.json) encodes this structure. Checks are intentionally absent, so its initial reader state is unchecked; the fixture does not invent source-backed verification.

## 4. Audit work, judgments, findings, and repairs

| Collection | Complete body fields |
|---|---|
| audits | `paper_id: ID; mode: enum(triage,focused,full); targets: [Target]; exclusions: [Exclusion]; protocol_version: string; independent_required: boolean; qualification_id: ID?; global_tasks: [GlobalTask]; report_path: string` |
| checks | `audit_id: ID; target: Ref; kind: CheckKind; role: enum(primary,independent); reviewer: string; protocol_version: string; state: enum(draft,complete); outcome: enum(supported,gap,refuted,inconclusive)?; reasoning: string; evidence_refs: [ID]; conditions: [string]; next_action: string?; response_id: ID?; supersedes: PinnedRef?` |
| findings | `audit_id: ID; target: Ref; category: enum(presentation,proof_gap,dependency_mismatch,statement_refutation,inconclusive); lifecycle: enum(open,resolved,superseded); description: string; evidence_refs: [ID]; check_refs: [PinnedRef]; affected_uses: [ID]; impact_reason: string; resolution: string?` |
| repairs | `finding_id: ID; kind: enum(supplemental_argument,restricted_statement,source_revision_proposal); description: string; supported_form: Target?; argument_id: ID?; added_conditions: [string]; evidence_refs: [ID]` |

`Exclusion = {"target": Ref|null, "source_anchor_ids": [ID], "reason": string, "consequence": string}`. At least a target or source location is supplied. `GlobalTask = {"kind": "global_consistency"|"adversarial"|"method_interface", "applicability": "required"|"not_applicable", "reason": string}`. Full/focused audits contain exactly these three task entries; any non-applicable task needs a reason. External-source obligations are per consumed result, not a global checkbox.

`CheckKind` is the closed list `derivation`, `application`, `composition`, `case_coverage`, `scope_discharge`, `external_source`, `global_consistency`, `adversarial`, `method_interface`.

| Check kind | Valid target | Meaning |
|---|---|---|
| derivation | groups | Local conclusion follows from all group inputs under its scope |
| application | uses | Supplier provides the exact needed form at this use |
| composition | arguments | Complete route establishes exact target, including all required parts and integration |
| case_coverage | groups with kind cases | Cases exhaust the declared target regime and are correctly assembled |
| scope_discharge | groups | Named local hypotheses/binders are discharged legitimately |
| external_source | items/parts | Authoritative outside statement and qualifications are verified in the exact consumed form |
| global_consistency, adversarial, method_interface | audits | Required cross-proof task for this declared audit scope |

A statement with well-posedness assertions may need its own argument; merely being a definition does not certify those assertions. Assumptions themselves are declared premises and need application checks where scope/applicability matters. Source-fidelity comparison remains an observation, separate from these mathematical checks.

Draft checks can be replaced while retaining all prior versions. A completed check requires nonempty reasoning, a non-null outcome, and enough recorded evidence/scope for its obligation. It is immutable. Corrections create a new check ID with a pinned `supersedes` reference and an explanation in reasoning. Supersession must keep the same audit, role, kind, and target; it cannot erase another reviewer's independent judgment. Two conflicting completed checks of the same inputs without explicit resolution remain disputed; never select a convenient latest row.

`refuted` requires evidence for the exact assertion and its hypotheses, including an instantiated counterexample when applicable. `gap` means the supplied argument does not establish its obligation. Both may lead to an unestablished theorem; only exact refutation evidence supports a false-statement assessment. A resolved finding requires a nonempty resolution and retained evidence. Resolution alone does not change source bytes or make an old check green.

A repair's verification state is derived from checks of its separate argument/form, not an editable `verified` flag. A restricted repair creates a separately identified statement, normally an intermediate item with `origin: proposed_repair` owned by the affected major result. Consumers use that exact form with explicit extra-condition checks. A supplemental argument may target the unchanged statement but retains `origin: proposed_repair`. Neither changes the finding on the written route. A manuscript change creates a new source version and reviewed bindings.

`Profile = {"provider": string, "model": string, "effort": string|null, "tools": [string], "context_isolation": string}`. `Calibration = {"case_id": string, "response_blob": string, "outcome": "pass"|"fail"|"inconclusive"}`. ### 5.1 Worker response and coordinator submission

There are two separately authored inputs. **The worker writes the mathematical response; the coordinator writes the submission envelope.** The coordinator passes the worker's file unchanged, not a parsed/reformatted copy or an edited judgment. All fields below are required; unknown fields are rejected. The worker-response interface is versioned by the identified packet's `packet_version`.

| Input | Complete fields | Author |
|---|---|---|
| Worker response (`RESPONSE.json`) | `packet_id: string; covered_targets: [Target]; coverage_note: string; exposure_report: ExposureReport; judgments: [Judgment]` | Independent worker |
| Submission envelope (`SUBMISSION.json`) | `contract_version: 3; request_id: string; packet_id: string; reviewer: string; qualification_id: ID; exposure: enum(source_only,compromised); exposure_note: string` | Coordinator, from the actual dispatch and qualification record |

`ExposureReport = {status: enum(none_known,possible_exposure), note: string}`. This reports the worker's own knowledge, not a guarantee of isolation. `Judgment = {target: Ref|SourceTarget, kind: CheckKind, state: enum(draft,complete), outcome: enum(supported,gap,refuted,inconclusive)?, reasoning: string, evidence_refs: [ID], conditions: [string], next_action: string?, supersedes: PinnedRef?}`. `SourceTarget = {source_anchor_id: ID, description: string}` supports a newly identified inference before canonical mapping. Other judgment fields have the check meanings in section 4. Empty judgments or missing scope coverage do not constitute a completed review.

The coordinator obtains reviewer identity and qualification ID from its dispatch records, not worker-authored fields. It sets `source_only` only after verifying the actual fresh-context instructions and tool/context access described in the handoff. Unverified or compromised dispatch is recorded as `compromised`, with the uncertainty or exposure explained in the nonempty note. This is coordinator-recorded evidence, not an operating-system isolation guarantee.

`review submit` and `submit_review(db, *, submission, response_bytes)` accept these exact two inputs. The tool validates the envelope, independent-mode packet, audit scope, and qualification/reviewer/protocol compatibility, then preserves the original response bytes before interpreting the worker's judgments. Worker and envelope packet IDs must match. Idempotency hashes the canonical envelope together with the SHA-256 of the original bytes; changing either under the same request ID is rejected.

Stored `responses.exposure` is `source_only` only when the coordinator verified source-only dispatch and the worker reports `none_known`. Otherwise it is `compromised`; the stored note retains both accounts. A worker's no-exposure claim cannot improve the coordinator's assessment. The tool generates the response/check IDs, original-blob hash, audit, role `independent`, protocol version, and evidence bindings, and returns a mapping from judgment positions to check IDs. Reviewer, qualification, and coordinator exposure metadata never come from the worker's JSON.

Supersedes is null for an initial judgment; a later independent response may explicitly supersede that same reviewer's earlier check under the same target/kind/role rules. A response that cannot be parsed or whose packet/scope cannot be validated is preserved with a diagnostic and `needs_revision` status, not converted into accepted checks. This preservation does not bypass invalid envelope or qualification checks.

Independent workers can identify new claims without seeing primary intermediate IDs. A SourceTarget appears only in the worker response, never as a canonical check target. The original response is preserved as `needs_revision` until the coordinator supplies an explicit source-grounded mapping to canonical targets. Store that mapping as an identity map with `response_id` provenance, never rewrite the response. Mapping cannot convert an incomplete review into full coverage; integration and omitted obligations remain required.

Checks derived from a response have `response_id` set; primary checks have null. The list of a response's checks is derived from that field. Accepted responses and reconciliations are immutable evidence; later assessments append successors with explicit references. Reconciliation requires coverage compatibility, current inputs, and accepted independent responses. `primary_revised`/`independent_revised` requires successor checks explaining the changed view. Unresolved disagreement remains amber. A source-only response's neutrality depends on actual dispatch context, not its self-reported label alone.

A successor reconciliation pins the prior reconciliation in `supersedes` and retains the same audit and target. Supersession chains must be acyclic. Multiple contradictory unsuperseded reconciliations remain disputed. Original response bytes and old judgments remain available after any supersession.

`review map` accepts `{contract_version: 3, request_id, packet_id, response_id, entries: [{judgment_index, target: Ref, rationale}], reviewer}`. The judgment index is zero-based in the preserved response. It cannot change kind, outcome, reasoning, or evidence. Save a new independent response for substantive changes. An unaccepted response may advance from needs_revision to accepted after all required mappings resolve, preserving its original blob and all prior versions. Generic `apply` cannot author independent checks, change response provenance, or substitute a hand-written response blob hash.

Reconciliation uses checks from accepted responses and must account for every accepted covering response. Historical `needs_revision` responses remain inspectable but grant no independent completion credit and do not permanently veto reconciliation of accepted evidence. A check from a still-pending response cannot be listed as accepted independent evidence. Correcting a response does not erase, relabel or automatically supersede its original. The coordinator must inspect pending diagnostics and preserve any scientific issue in an appropriate finding or unfinished judgment; the script does not infer that an omitted issue was resolved.

Each reconciliation targets the exact statement, argument, group or use of its compared checks. Statement-level independent completion combines current, non-superseded resolved rows across those targets, requires every required independent obligation to be satisfied, and requires the nonempty set of current accepted independent judgments to be covered. An unresolved applicable row prevents completion until explicitly resolved or superseded. Stale rows grant no current coverage, and newly accepted judgments require corresponding reconciliation.

## 6. Generated bindings, currentness, and support

Binding format is generated JSON associated with an exact owner record version:

```text
{records: [{ref: PinnedRef, facet: Facet, digest: SHA256}],
 relations: [{relation: string, key: Ref, digest: SHA256}],
 source_context_digest: SHA256, packet_id: string}
```

`Facet` is `statement`, `proof`, `application`, `inference`, `scope`, `coverage`, `source`, or `full`. Canonical JSON hashing uses UTF-8, sorted object keys, compact separators, unchanged string values, no NaN/Infinity, and preserved array order. Relation hashes sort by collection/ID. This is the same canonicalization for request idempotency. Facet recipes are fixed, not free-text worker choices:

| Facet | Included content |
|---|---|
| statement | For items/parts: statement form/text, origin, scope ID and statement/definition passage IDs; parts also include their parent item ID. Excludes printed label/caption/aliases and source coordinates. For statement/definition anchors: exact excerpt content, excluding locator/source-version metadata |
| proof | For items/arguments: local passage/evidence IDs and origin. For proof anchors: exact excerpt content, excluding locator/source-version metadata |
| application | Use endpoints including selected parts, type, needed form, substitutions, regime, reason, evidence, and inference membership |
| inference | Group conclusion/kind/scope ID, case/discharge lists, rationale, and source evidence IDs; input membership is a separate relation binding |
| scope | Local parent/argument IDs, assumption references, binders, conditions, and evidence IDs; referenced scopes and statements bind separately |
| coverage | Audited spans/classifications/claim assignments; completion also guards responsible check membership |
| source | Exact captured source/anchor versions, selected branches, macro/context reviews |
| full | All body fields, for provenance/reconciliation operations where no narrower facet is sufficient |

Every cached facet is strictly a function of its own record version. Binding construction walks the finite set of referenced records with a visited set and records their facets and relation memberships separately; it does not hash recursive expansions into an unchanged owner's facet. Thus adding a use changes an inference's membership guard without rewriting group version 1's cached facet. A scope may legitimately reference an assumption whose own scope ID points back to that scope; this is not a circular proof. Detect cycles only in containment or the actual selected inference dependencies as appropriate.

Exact source versions/positions remain pinned in the separate source bindings. A relocation can preserve statement/excerpt content facets while changing source provenance. A global source-context digest changes whenever a registered relevant source changes. This requests context review, not automatic regeneration of every mathematical argument. After a reviewer assesses changed macros, assumptions, declarations, and exact anchor relocations, a reuse decision may carry eligible unchanged reasoning.

| Collection | Complete body fields |
|---|---|
| reuse_decisions | `check_ref: PinnedRef; source_review_id: ID; decision: enum(reusable,recheck); rationale: string; evidence_refs: [ID]` |

Its generated binding includes the old and new context digests and all checked semantic facets. `reusable` is accepted only when changed bindings are exact source relocation/context changes approved by the review and consumed mathematical facets are unchanged. A changed statement/inference is not eligible for this command; save a new check. A reuse decision never edits original check evidence.

| Check | Required bindings |
|---|---|
| application | Exact use, supplier's consumed statement/part and statement excerpts, target needed form, consumed supplier and local scope chains, use-site evidence; borrowed proof passage membership and exact excerpts when type is proof_argument |
| derivation | Group inference, all required use applications, local scope, consumed source proof spans |
| composition | Target exact statement/parts, route's required groups, cases/discharges, scope, coverage and integration evidence |
| external_source | Authoritative source statement/assumptions/location and consumed form |
| global tasks | Declared audit scope and the precise records/relationships examined by that task |

Mathematical judgments have derived `freshness: current|needs_review|historical` and `dependency_support: available|conditional|unavailable`. Historical means superseded or bound to a historical target version; needs_review means still the active saved judgment but relevant current input/context requires review. Preserve its original outcome visibly in both cases.

Dependency support is computed separately from local check freshness. A premise explicitly declared as an assumption in scope is available as that assumption, not claimed proved. An internal unverified supplier makes its consumers conditional. A confirmed refutation or incompatible application makes the claimed supplied form unavailable. Changing a supplier proof while preserving its statement does not erase the consumer's conditional local reasoning; it may change support. A proof_argument use consumes the borrowed proof and therefore reacts to that passage changing. Outgoing consumers never enter a supplier's local binding.

## 7. Completion, exports, and migration

| Collection | Complete body fields |
|---|---|
| identity_maps | `reason: enum(import,split,merge,successor,response_mapping); source_blob: string?; response_id: ID?; entries: [Mapping]; reviewer: string; note: string` |

`Mapping = {"old": string, "new_refs": [Ref], "rationale": string}`. Unknown mappings have an empty destination list and remain unresolved. Mapping provenance does not grant mathematical reuse.
